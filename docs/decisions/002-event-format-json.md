# ADR-002: JSON як формат події журналу

- **Дата:** 2026-09-02
- **Статус:** прийнято
- **Область:** архітектура

## Контекст

Спайк 2026-09-02 (PRD, розділ 6.4) показав, що читання 10 000 подій займає **0.43 с** — удвічі більше за guardrail 200 мс. Події у спайку зберігалися в YAML.

Потрібно було встановити, що саме є причиною: кількість файлів, файлова система чи парсер.

Заміряно на тих самих 10 000 подій:

| Формат | Парсинг 10k подій | Байтів на подію |
|---|---|---|
| JSON (`JSON.parse`) | **6 мс** | 174 |
| YAML (`yaml` 2.9.0) | **496 мс** | 150 |

Різниця — **83×**. Тобто майже весь виміряний у спайку час був не введенням-виведенням, а YAML-парсером.

## Розглянуті варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| JSON | Нативний парсер, 83× швидше; нуль залежностей; `JSON.parse` не виконує коду | На 24 байти більше на подію; лапки в ключах трохи гірше читаються оком |
| YAML | Приємніший людині; менший обсяг | 496 мс на 10k подій — сам по собі перевищує весь бюджет CLI; тягне залежність на 686 КБ |
| JSONL (рядок = подія) | Компактно, швидко | Повертає до спільного файлу, а це 2 конфлікти з 3 за вимірами спайку — суперечить головній гіпотезі продукту |
| MessagePack та інші бінарні | Найшвидше й найкомпактніше | Вбиває `git diff` як людиночитаний журнал — а це головна перевага продукту |

## Рішення

**JSON, один об'єкт на файл, без відступів** (`JSON.stringify` без `space`).

Аргумент читабельності, який зазвичай грає за YAML, тут майже не важить: подія має 7 полів і показується користувачеві через `flowit log`, а не читається з файлу очима. Там, де читабельність справді потрібна — в описах задач — залишається Markdown із frontmatter (ADR-005).

## Наслідки

- Позитивні: 83-кратне прискорення парсингу за нуль рядків коду; мінус одна залежність; `git diff` на однорядковому JSON показує зміну як цілу подію, а не як набір рядків.
- Ціна рішення: +14% до розміру журналу; `cat` на файлі події менш приємний, ніж міг би бути.
- Що доведеться переглянути: якщо події колись доростуть до вкладених структур на десятки полів, однорядковий JSON стане нечитаним у diff — тоді варто перейти на JSON з відступами, а не на YAML.

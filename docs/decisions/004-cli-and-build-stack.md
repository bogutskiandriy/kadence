# ADR-004: CLI-шар і збірка

- **Дата:** 2026-09-02
- **Статус:** прийнято
- **Область:** стек

## Контекст

ADR-003 звільнив ядро від залежностей, але шар CLI має завдання, де власна реалізація вже не окупається: розбір аргументів, генерація `--help`, підказки при друкарській помилці в назві команди.

## Розглянуті варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| `cac` 7.0.0 | 3.3 мс — найдешевший із протестованих; 41 КБ; вбудований `--help` | Проєкт давно без релізів — ризик занедбаності |
| `citty` 0.2.2 | Активно розвивається (UnJS); 35 КБ | 8.3 мс — удвічі дорожче; версія 0.x, API ще може змінитися |
| `commander` 15.0.0 | Де-факто стандарт, найкраща документація | 17.1 мс — 11% бюджету лише на розбір аргументів |
| Власний парсер | 0 мс | `--help`, підкоманди й помилки користувача — це не 80 рядків, а постійний борг |

## Рішення

| Роль | Вибір | Чому |
|---|---|---|
| Розбір аргументів | **`cac`** | Найдешевший; API стабільний саме тому, що проєкт завершений |
| Кольори | **власні ANSI-константи** | ~10 рядків із перевіркою `NO_COLOR` і `isTTY`; `picocolors` коштує 7.7 мс за те саме |
| Таблиці | **власний рендер** | Ширина колонок для трьох полів; `cli-table3` тягне `string-width` |
| Frontmatter | **власний парсер** | `gray-matter` — 13 мс і залежність на `js-yaml`; нам треба зчитати кілька рядків `key: value` до `---` |
| Збірка | **esbuild** | 147 КБ, без залежностей; `tsup` — це обгортка, що тягне `cac`, `chokidar`, `consola` |
| Тести | **vitest** | Дев-залежність, на бюджет рантайму не впливає |

Щодо ризику `cac`: він локалізований в одному модулі (M6), який лише описує команди й передає розібрані аргументи в ядро. Заміна парсера не торкнеться жодного модуля ядра — це кілька годин роботи, а не переписування.

## Уточнення від 2026-09-02 (за результатом реалізації)

**`cac` не підтримує багатослівні команди.** Оголошення `cli.command('task add <title>')` потрапляє у `--help` і виглядає робочим, але жодна дія не викликається: `matchedCommand` лишається порожнім, і CLI тихо завершується з кодом 0. Виявлено при першій наскрізній перевірці.

Обхід — патерн `task <action> [title]` з розбором дії всередині обробника. Ціна: `--help` для окремої підкоманди доводиться писати самим.

Це не змінює рішення: `cac` лишається найдешевшим за виміром (3.3 мс проти 8.3 у `citty`). Але ризик у ADR був названий неправильно — очікувалася занедбаність проєкту, а справдилося обмеження функціональності. Якщо підкоманд стане більше трьох рівнів, перехід на `citty` окупиться.

## Наслідки

- Позитивні: сумарна вартість імпорту рантайм-залежностей — 3.3 мс замість 40+; ядро лишається придатним для вбудовування як бібліотека.
- Ціна рішення: власні кольори, таблиці й frontmatter — це код, який доведеться підтримувати; кожен із них має бути тривіальним, і якщо котрийсь почне рости — це сигнал брати бібліотеку.
- Що доведеться переглянути: якщо `cac` перестане працювати на новій мажорній версії Node — переходимо на `citty`, платимо 5 мс.

# ADR-007: Що потрапляє в репозиторій

- **Дата:** 2026-09-03
- **Статус:** прийнято
- **Область:** репозиторій, інструментарій

## Контекст

Проєкт, який продає ідею «задачі — це звичайні файли в git», сам заріс тим, що в git бути не мало. Заміри на 2026-09-03, до цього рішення:

| Що | Файлів | Розмір |
|---|---|---|
| `.claude/skills/` — загальна бібліотека скілів агента | 381 | 3.8 МБ |
| `.serena/` — конфіг і кеш індексатора | 2 | 20 КБ |
| решта: `src/`, `test/`, `docs/`, конфіги | 94 | ~750 КБ |
| **разом у git** | **491** | |

Тобто **80% файлів репозиторію не мали стосунку до продукту**. Наслідки не косметичні:

- `git clone` вантажить 3.8 МБ чужої бібліотеки заради CLI на 30 КБ;
- у `.serena/project.yml` — абсолютні шляхи машини автора (`/Applications/...`), тобто файл конфліктує в кожного, хто його відкриє;
- `.claude/skills/product-lean-canvas/scripts/__pycache__/*.pyc` — скомпільований байткод чужого Python, який приїхав у git разом із рештою;
- у діффі PR тоне те, що справді змінилося.

Старий `.gitignore` складався з чотирьох рядків і не покривав ні `.DS_Store`, ні `.env`, ні coverage.

## Розглянуті варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| Лишити як є | Нуль роботи; налаштування агента однакові в усіх | 80% репозиторію — чуже; локальні шляхи конфліктують |
| Комітити `.claude/`, крім `skills/` | Команди `/eng-*` доступні контриб'юторам | Команди викликають скіли, яких у репозиторії вже нема — половина інструмента |
| **Не комітити інструментарій агента взагалі** | Репозиторій = продукт; контракт для агентів уже є й він tool-agnostic | Кожен розробник ставить свої скіли сам |

## Рішення

**У git іде те, без чого не можна відтворити або зрозуміти продукт. Усе інше — ні.**

**Комітимо:**

- `src/`, `test/`, `scripts/build.mjs` — код і його перевірка;
- `package.json`, `package-lock.json`, `tsconfig.json`, `vitest.config.ts` — lock-файл обов'язково: без нього CI ставить не ті версії, що людина;
- `docs/`, `SPEC.md`, `README.md`, `CHANGELOG.md`, `LICENSE`, `tasks/` — чому і що саме зроблено;
- `.github/workflows/` — CI як частина визначення «готово»;
- `AGENTS.md` і `.kadence/README.md` — **контракт для агентів**: він описує CLI й формат JSON, а не конкретний інструмент, тому корисний і для Claude, і для будь-чого іншого;
- `.kadence/events/` — журнал подій. Це і є дані продукту; сенс kadence саме в тому, що вони лежать у git поруч із кодом.

**Не комітимо:**

- `node_modules/`, `dist/` — відтворюються з lock-файла і `npm run build`; `dist/` до того ж публікується в npm, тому в git він лише конфліктував би на кожному злитті;
- `.kadence/state.json` — похідний знімок, перебудовується з подій; тримати його в git означало б мати два джерела правди й конфлікт на кожен рух задачі;
- `.claude/`, `.serena/`, `.cursor/`, `.aider*` — інструментарій розробника. Він у кожного свій, ставиться окремо і містить абсолютні шляхи. Виняток лишено один: `.claude/settings.json` — спільні налаштування проєкту, якщо вони колись знадобляться;
- `.env` і секрети — ніколи; для прикладу є `.env.example`;
- `.DS_Store`, `.idea/`, `.vscode/`, `*.swp` — сміття ОС і редакторів;
- `coverage/`, `*.log`, `*.tsbuildinfo` — артефакти прогонів.

Правило для нового файлу — одне питання: **чи зможе хтось інший відтворити або зрозуміти продукт без нього?** Якщо ні — комітимо. Якщо файл генерується, кешується або описує машину автора — ні.

## Наслідки

- Позитивні: у git 94 файли замість 491; діфф PR показує зміни продукту, а не чужої бібліотеки; зникло джерело конфліктів через абсолютні шляхи.
- Ціна: контриб'ютор не отримує команд `/eng-*` разом із клоном і ставить свої скіли сам. Прийнятно: `AGENTS.md` описує, як працювати з проєктом, без прив'язки до інструмента.
- `git rm --cached` прибирає файли з індексу, але не з історії — `.git` лишається 18 МБ. Переписувати історію (`git filter-repo`) на вже опублікованому репозиторії ми не стали: це ламає всі клони заради місця, якого не бракує.
- Що доведеться переглянути: якщо в проєкт прийде постійна команда і однакове середовище агента стане частиною процесу — тоді `.claude/` повертається в git цілим, разом зі скілами, а не наполовину.

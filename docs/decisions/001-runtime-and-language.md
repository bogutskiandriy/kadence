# ADR-001: TypeScript на Node.js як рантайм ядра

- **Дата:** 2026-09-02
- **Статус:** прийнято
- **Область:** стек

## Контекст

sprintit має запускатися через `npx sprintit` без попереднього встановлення — це вимога з PRD (розділ 7.1). Guardrail на старт CLI — 200 мс на 1000 задач.

Виміряно на машині розробки (Node v25.8.2):

| Що | Час |
|---|---|
| Холодний старт порожнього Node-процесу | **40 мс** |
| Залишок бюджету на всю роботу CLI | **160 мс** |

40 мс — це 20% бюджету, витрачені ще до першого рядка нашого коду. Це головне обмеження, від якого залежать решта рішень у стеку.

## Розглянуті варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| TypeScript + Node | `npx` працює без інсталяції; найбільша аудиторія OSS-контриб'юторів; типи як виконувана специфікація подій | 40 мс з'їдено стартом рантайму; потрібен крок збірки |
| Go | Старт ~2 мс; один статичний бінарник; ідеальний для CLI | Немає `npx` — потрібні Homebrew/scoop/curl-скрипт для кожної платформи, що вбиває сценарій «спробувати за 30 секунд» |
| Rust | Найшвидший; надійність через типи | Те саме, що Go, плюс вищий поріг входу для контриб'юторів OSS-проєкту |
| Deno / Bun | Швидший старт за Node | Аудиторія вужча; `npx` — досі домінантна звичка |

## Рішення

**TypeScript, збірка в ESM, ціль Node 20+.** Мінімальна версія — 20 LTS, а не поточна 25: вимагати свіжий Node від користувача, який просто хоче спробувати інструмент, суперечить обіцянці «нуль налаштувань».

Дистрибуція — один бандл, зібраний esbuild-ом. Причина не в розмірі файлу, а в кількості звернень до файлової системи: кожен `import` у неспакованому `node_modules` — це окремий resolve, а вони й формують ті мілісекунди, що вимірювалися нижче в ADR-003.

## Наслідки

- Позитивні: `npx sprintit` працює одразу; типи подій — водночас документація й перевірка.
- Ціна рішення: 40 мс бюджету назавжди віддані рантайму; решта ADR-ів існує лише тому, що ця ціна вже сплачена.
- Що доведеться переглянути: якщо профіль покаже, що ми стабільно виходимо за 200 мс навіть із порожнім ядром, єдиний вихід — переписати ядро на Go і відмовитися від `npx` на користь бінарників. Це рішення варте окремого ADR і не приймається до появи вимірів на реальних репозиторіях.

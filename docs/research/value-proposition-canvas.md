# Value Proposition Canvas — FlowIt

- **Дата:** 2026-09-02
- **Сегмент:** один — розробник у терміналі, що працює з AI-агентом (окремий канвас на сегмент; тех-лід і PM тут не змішані)
- **Джерело доказів:** конкурентний аналіз + технічний спайк. **Інтерв'ю не проводилися**
- **Рівень fit, який перевіряємо:** problem-solution

> За методом Strategyzer (Osterwalder, *Value Proposition Design*, 2014). Канвас, заповнений без інтерв'ю, за визначенням є чернеткою.

## Профіль клієнта

### Роботи (за важливістю)
1. Дати агенту контекст задачі без ручного переказу — **висока**
2. Вести задачі, не покидаючи термінал — **висока**
3. Розбити велике на шматки, посильні агенту за один прохід — **висока**
4. Знати, скільки насправді зайняла робота — середня
5. Не втратити чужі зміни при злитті — **невідома**

### Болі (гострота × частота)
| Біль | Оцінка | Хто вже лікує |
|---|---|---|
| Переказ контексту агенту | висока × щодня | Backlog.md (MCP), git-issues (`.agent.md`) |
| Розрив уваги через браузер | середня × щодня | усі троє (CLI + TUI) |
| Оцінки без зворотного зв'язку | середня × щоспринту | **ніхто** |
| Трекер розходиться з кодом | середня × щотижня | частково — усі файлові |
| Конфлікти при злитті | **?** × **?** | **ніхто** |

### Здобутки
- Агент стартує з контекстом **must-have**
- Борд однією командою **must-have**
- Velocity без ручної роботи *nice-to-have*
- Повна історія проєкту через `git checkout` *nice-to-have*
- Злиття без ручного розбору задач **?**

## Карта цінності

### Продукт
CLI-трекер із append-only журналом подій у `.flowit/`, спринтами й контрактом `--json` для агентів.

### Знеболювачі
| Наш засіб | Проти якого болю | Чи є в конкурентів |
|---|---|---|
| `.flowit/` як звичайні файли + `--json` | Переказ контексту агенту | **Так** — MCP, `.agent.md` |
| CLI-команди, старт ≤ 200 мс | Розрив уваги | **Так**, і в них ще TUI |
| Journal-derived velocity | Оцінки без зворотного зв'язку | **Ні** |
| Append-only журнал | Конфлікти при злитті | **Ні** |
| Стан у файлах під версійним контролем | Розходження з кодом | Так (крім git-bug) |

### Творці здобутків
- Спринт закривається сам, velocity рахується з подій — **унікально**
- `git checkout` повертає тодішній борд — унікально серед файлових; git-bug цього не дає, бо тримає дані в git-об'єктах
- Нуль конфліктів навіть коли троє правлять одну задачу — **унікально**, виміряно

## Оцінка fit

| Біль клієнта | Наша відповідь | Fit |
|---|---|---|
| Переказ контексту агенту | Файли + `--json` | **Слабкий** — біль справжній, але вже вилікуваний конкурентами; ми не кращі, ми такі самі |
| Розрив уваги | CLI | **Відсутній у v0.1a** — у них TUI, у нас список |
| Оцінки без зворотного зв'язку | Velocity з журналу | **Сильний** — біль правдоподібний, лікаря немає |
| Розходження з кодом | Файли в репо | Частковий — не наша перевага |
| Конфлікти при злитті | Append-only | **Сильний, але непідтверджений** — унікальний засіб проти болю невідомої гостроти |

## Головний висновок

**Проблемно-рішенєвий fit не досягнутий, і канвас показує, чому саме.**

Там, де болі підтверджені доказами, ми **не унікальні** — конкуренти вже їх лікують, а в частині випадків краще за наш v0.1a. Там, де ми унікальні, **болі не підтверджені**.

Це класична форма провалу за Strategyzer: карта цінності добре побудована, але дзеркалить не ті елементи профілю.

Два виходи, і вони не виключають один одного:
1. **Перевірити болі №3 і №5 інтерв'ю.** Підтвердяться — fit сильний і продукт має право бути.
2. **Не випускати v0.1a без борду.** Проти конкурентів із TUI список у терміналі програє ще до того, як користувач дізнається про append-only.

## Найгостріші неадресовані елементи

1. Гострота болю «конфлікти» невідома — а на ньому тримається архітектура
2. Розрив уваги в v0.1a не адресований взагалі (TUI відкладено на v0.1b)
3. Ми не маємо жодної переваги в тій роботі, яка найкраще підтверджена доказами — контекст для агента

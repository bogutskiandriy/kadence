**Інтеграційний тест знайшов баг, який пройшов повз 147 попередніх тестів.**
`.flowit/events/` зникає цілком при перемиканні на гілку без подій — git не версіонує порожні директорії. CLI у цій ситуації вимагав повторного `init` на цілком робочому репозиторії. Перевірка дивилася на теку подій замість `.flowit/`. Виправлено, додано регресійний тест.

**Друга знахідка — хибна евристика виявлення злиття.** Перша версія рахувала події «з минулого» (з меншим ULID). Демонстрація показала, що після злиття чужі події мають БІЛЬШИЙ ULID, якщо створені пізніше за наші. Замінено на визначення за авторством.

### Checkpoint 8 — аудит перед релізом ✅ 2026-09-03

Прогнав усі команди в семи станах: поза репозиторієм, без `init`, порожній журнал, неіснуючі сутності, межові дані, пошкоджений журнал, зникла тека подій.

**Знайдено й виправлено три вади:**

| Вада | Було | Стало |
|---|---|---|
| `flowit task` без дії | сире `missing required args` від cac | власна підказка з переліком дій |
| `--estimate -5` | `Unknown option -5` — cac з'їдав як прапорець | перехоплення до розбору, повідомлення про оцінку |
| Назва на 250 символів | розтягувала борд і список | обрізається до 72 символів; повна лишається в `show` і в JSON |

Остання вада була описана в [edge-cases.md](../docs/design/edge-cases.md), але не реалізована — знайдена лише прогоном.

**Перевірено як правильне:** порожні стани підказують наступний крок; неіснуючі сутності дають код 1; помилки аргументів — код 2; пошкоджений журнал попереджає й показує решту; зникла тека подій відновлюється; емодзі й не-ASCII не ламають вирівнювання; `estimate 0` і `2.5` приймаються свідомо.

**Три рішення:**
- **«Усе або нічого» для груп.** Якщо хоч один ID не існує — не виконується жодна дія. Наполовину застосована групова зміна складніша для відкату, ніж та, що не почалася.
- **Порожній результат називає фільтри**, які його дали: `No tasks match type=bug and priority=low`. Просте «нічого не знайдено» лишає гадати, чи борд порожній, чи запит завузький — а це протилежні наступні кроки.
- **Назву не можна поставити групі.** Застосувати одну назву до кількох задач означало б їх продублювати, а не відредагувати.

### Checkpoint 11

- [x] Ієрархія epic → story → subtask відображається деревом
- [x] Заблоковані задачі позначені `[blocked]`
- [x] Цикл показується, обидві дуги лишаються живими
- [x] 303 тести

**Рішення, зафіксовані в коді:**

- **Епік — це `type: epic`, а не нова сутність.** Дві паралельні ієрархії (епік→задача і батько→дитина) розійшлися б у поведінці; одна не може.
- **Цикл ніколи не відхиляється.** Відхилення пізнішої події зробило б стан залежним від порядку злиття гілок і зламало б інваріант I1. Обидві дуги живуть, CLI попереджає з повним шляхом циклу.

- **Посилання на видалену задачу обнуляються при згортанні** — інакше дерево вказувало б на неіснуючі вузли.
- **Тест продуктивності тепер бере найкращий із трьох запусків.** Він упав через навантаження від сусідніх тестів, а guardrail, який падає випадково, швидко перестають поважати.

### Checkpoint 12

- [x] Burndown малює фактичну лінію проти ідеальної, з відхиленням числом
- [x] Логовані години в звіті спринту окремо від виведених
- [x] `task add --template bug` підставляє поля, явний прапорець завжди виграє
- [x] 314 тестів

**Рішення:**

- **Burndown відновлюється з журналу, а не накопичується щодня.** Трекер, який пише «залишилось сьогодні», не відповість про минуле й втрачає графік, якщо тиждень ніхто не заходив. Журнал знає час кожного переходу, тож графік будується заднім числом.
- **Повторне відкриття задачі повертає пункти на графік.** Рахувати `done` один раз означало б показувати завершеною роботу, якої вже немає.
- **Відкритий спринт не малюється в майбутнє** — порожній календар праворуч читається як дані.
- **Логовані години й виведені — різні числа.** Одне каже, скільки людина витратила за власними словами, друге — скільки минуло за бордом. Змішувати їх означало б втратити обидва сенси.
- **`task log` обробляється до розбору аргументів.** cac їсть `-30m` як прапорець; замість боротьби з бібліотекою цей випадок перехоплюється раніше.

### Checkpoint 13

- [x] Команда задає свої колонки, вони зливаються з гілок як усе інше
- [x] `done` обов'язковий — на ньому тримаються velocity й burndown

**Рішення:**

- **`TaskStatus` перестав бути закритим union і став `string`.** Тип не може перелічити те, що команда вигадає сама; натомість валідація перенесена в CLI, який знає конфігурацію.
